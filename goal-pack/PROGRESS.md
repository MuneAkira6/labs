## Handover (filled at the end; each item = fact, impact, the decision needed)

1. **Every committed result file says `commit: eb6646f+dirty`.** SCOPE.md 1.4 requires `+dirty` when
   `git status --porcelain` is not empty, and it never was: the run does not commit, so the tree held
   uncommitted deliverables throughout. *Impact:* once the human commits, each result file names a
   commit that does not contain it, and a reader cannot recover the exact tree from the field alone.
   *Decision needed:* accept that and rely on the ledger's `Build under test` digests, or re-run the
   three labs after the first commit so the files name a clean commit — which costs about three
   minutes and replaces the committed results.
2. **Each lab holds two dated result sets, `2026-10-05` and `2026-10-06`.** G5's final runs crossed
   midnight UTC and the naming rule of 1.4 is per date. *Impact:* the repository publishes two real
   runs of the same build per lab; the README quotes only the later. *Decision needed:* keep both as
   evidence that two runs agree, or prune the earlier set before publishing — noting that G2, G3 and
   G4's ledger rows quote the earlier files, so pruning leaves those rows pointing at files that no
   longer exist.
3. **The contract changed once, at 4.4.** html-webpack-plugin 5.6.8 strips attribute quotes in
   production whatever `minify` says, so the emitted webpack page reads `id=root` (facts F20).
   *Impact:* anyone comparing the published HTML with the frozen contract will see the difference.
   *Decision needed:* publish as is with the AS-BUILT note, or pin a plugin version that honours
   `minify` if one exists — which the run could not check, having no network.
4. **CI has never executed.** The workflow is syntactically clean by actionlint and every action is
   pinned to a SHA of facts F12, but the run cannot reach GitHub, so no job has ever started.
   *Impact:* the first push is also the first test of the workflow; the lab jobs in particular pull
   the MongoDB and sbt images, which this machine never does. *Decision needed:* expect to iterate on
   the first CI run, and decide whether the three lab jobs should block a merge or be advisory until
   they have passed once.
5. **The labs have run on one Linux host only.** The runbook plans a Windows re-run by the author.
   *Impact:* the portability rules of SCOPE.md 1 are implemented but only partly exercised here —
   `pathToFileURL` has no run-time dynamic import to protect in the end, since the runners spawn
   processes rather than importing by path. *Decision needed:* when the Windows results arrive, add
   them beside the Linux ones and update 結果 and 制約・既知の限界, as the runbook's section 7 says.
6. **`Lab.scala` compiles with 7 warnings.** They ask for a `using` clause where the contract's own
   table writes the execution context positionally, `Future { … }(pool)`. *Impact:* cosmetic; the
   build succeeds and the behaviour is the contract's. *Decision needed:* leave the code in the
   contract's form, or adopt `using` and note the divergence from the text of 3.1.
